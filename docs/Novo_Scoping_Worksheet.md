# NOVO — Scoping Worksheet (v1 planning)

*Companion to the Novo brief. The brief is the DREAM (the experience). This is the CUT (the smallest buildable thing that still delivers a sliver of the feeling).*

*Mode note: designing the experience was generative + joyful — every session ADDED something. Scoping is the opposite — subtractive, slightly painful, parking beautiful things so a small real version can exist. This is where projects stall (dreaming was fun; cutting isn't). But it's the SAME instinct you're already good at — you design by subtraction (random not attuned, no visitors, empty loft). This is that instinct aimed at the build. Making v1 tiny isn't betraying the full Novo — it's the closure-ritual move: keep the rest safe + waiting while you tend the one thing you can finish.*

## Q2. FEELING-PER-EFFORT — sort the elements
*Every element delivers some FEELING for some EFFORT. The ratios differ wildly. Build top-down: cheap-but-deeply-felt first.*

Rough sort to react to / correct (F = feeling delivered, E = effort to build):
- Warm palette / colour — HIGH F, LOW E (mostly CSS)

## Q4. THE FRONT END — what's literally on screen + how it behaves
*This is where scoping becomes the interface. The practical decisions.*

- Is v1 the flat 2D PAN-CANVAS, or even simpler — a single still warm SCREEN, no navigation, just *a place*? (There may be a version BELOW the pan-canvas.)
> 
- What is literally on the screen? (tree? light? one plant? the board?) How many elements before it's "enough"?
> 
- Does v1 have the ENTRANCE, or do you drop straight into the room and add the procession later? (Entrance = gorgeous but also effort + a barrier to quick testing.)
> 
- STATIC or MOVING? (Still image = least build. Gentle drift/parallax = more. Is v1 still, motion in v2?)

- Full-bleed / no chrome from the start? (cheap, high immersion payoff — probably yes)

## THE SHAPE OF THE ANSWER
*Q1-Q3 earn the right to start drawing the front end (they say what it's FOR and how little you need). Q4 is the front end itself. Q5-Q6 keep it honest + finishable.*

Order of thinking: CORE (Q1) -> RATIO-SORT (Q2) -> EXCLUSIONS (Q3) -> INTERFACE SPECIFICS (Q4) -> MINIMUM STATE (Q5) -> SUCCESS CONDITION (Q6).

When these are answered, you have a v1 spec: a small, finishable, feeling-delivering first build — and a clear, safe, named pile of everything deliberately left for later.
